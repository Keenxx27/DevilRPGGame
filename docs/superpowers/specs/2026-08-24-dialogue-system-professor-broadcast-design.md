# 对话系统与教授广播设计

## 目标

为项目加入显示在屏幕下方的标准 Unity Canvas 对话框，并建立可复用的“广播”和“私聊”对话机制。本次同时配置教授的课堂广播，以及紧随其后的主角疼痛感受与内心独白。

## 已确认交互规则

- 广播自动开始；广播播放后使用 `R` 翻页。
- 私聊仅在玩家接触相应角色后，按 `R` 开始；开始后同样使用 `R` 翻页。
- 每页文字以每秒12个显示字符的速度逐字出现，标点也计入显示字符。
- 当前页尚未显示完毕时，`R` 无效，不补全文字也不翻页。
- 当前页显示完毕后，`R` 进入下一页；最后一页显示完毕后再次按 `R` 结束对话。
- 空格键在对话的任何时刻直接跳过当前整段对话。
- 对话期间属于剧情过场：玩家不能移动、开门、拾取、丢弃或切换物品栏槽位。
- 对话正常结束、被跳过或播放失败时，游戏输入都必须恢复。

## 视觉设计

采用已选择的方案 A：

- 新增独立的标准 Unity Canvas，排序层级高于物品栏。
- 对话框锚定屏幕底部，两侧和底边保留稳定边距。
- 背景为高不透明度深色，边框为金色。
- 左上显示金色发言者名称，正文使用白色。
- 右下显示 `R 继续　Space 跳过`。
- 逐字显示期间将 `R 继续` 视觉弱化；当前页完成后恢复正常亮度。
- Canvas 可保持启用，但对话面板默认隐藏，只在播放期间显示。
- 使用 `UnityEngine.UI.Text`；运行时优先创建 Microsoft YaHei 或 SimHei 系统动态字体，并以 Arial 为最后回退，保证当前 Windows 测试环境中的中文可见。

## 架构

### DialoguePage

可序列化的数据单元，只包含：

- `speaker`：发言者名称。
- `text`：该页完整正文。

### DialoguePlayback

不依赖场景生命周期的播放状态对象，负责：

- 当前页索引。
- 当前页已显示字符数量。
- 每秒12字符的逐字推进。
- 当前页是否显示完毕。
- 仅在当前页完成后允许翻页。
- 最后一页完成后的结束状态。
- 跳过整段对话。

纯状态逻辑与 Unity 输入分离，以便进行确定性测试。

### DialogueController

挂载在 `Main Character` 上，是唯一读取 `R` 和空格键的对话脚本：

- 空闲时按 `R`，尝试启动当前范围内最近的私聊来源。
- 播放时按 `R`，只在当前页完成后翻页或结束。
- 播放时按空格，立即结束整段对话。
- 每帧推进 `DialoguePlayback` 并刷新 `DialogueHUD`。
- 开始对话时记录并禁用 `MainCharacterMovement`、`PlayerInteraction` 和 `PlayerInventory`。
- 结束或失败时恢复这些组件在对话开始前的启用状态。
- 同一时间只接受一段对话；正在播放时拒绝其他广播或私聊请求。
- 管理进入范围内的私聊来源，并按距离选择最近对象。

### DialogueHUD

只负责显示：

- 发言者名称。
- 当前已显示的正文片段。
- `R` 和空格操作提示。
- 当前页未完成时的 `R` 提示弱化状态。

配置缺失时返回失败，由控制器结束播放并恢复输入，不允许角色永久处于锁定状态。

### BroadcastDialogueTrigger

- 保存一段 `DialoguePage` 数组和目标 `DialogueController` 引用。
- 在 `SampleScene` 首次启动后自动请求播放一次。
- 单个组件实例只触发一次。
- 教室场景在走廊 Additive 加载后仍保持加载，因此从走廊返回不会重复播放。
- 重新开始 Play Mode 时场景状态重置，广播会重新播放。

### PrivateDialogueTrigger

- 保存一段 `DialoguePage` 数组。
- 玩家进入 Trigger 时向 `DialogueController` 注册，离开时注销。
- 自身不读取 `R`；只有控制器读取输入，避免多个脚本争用同一按键。
- 本次建立通用能力，但不为教授配置私聊内容；教授仅使用广播。

## 教授广播内容与分页

整段广播包含10页，按以下顺序播放：

1. `教授`：`所以同学们要明确，`
2. `教授`：`恶魔是归墟侵蚀具象化的、充满攻击性的副产物。`
3. `教授`：`恶魔猎人的任务，就是像清除癌细胞一样，将它们从地球的肌体上彻底清除。`
4. `主角`：`（左脸被归墟侵蚀的痕迹……正在发热、灼痛。）`
5. `主角`：`如果它们只是动物。`
6. `主角`：`如果它们中，有比动物更复杂的存在。`
7. `主角`：`我们到底在做什么？`
8. `主角`：`也许我该去图书馆看看......`
9. `主角`：`不知道我的借书卡去哪里了，`
10. `主角`：`可能是被哪个家伙藏起来了。`

按空格跳过时，以上10页全部结束，不再继续播放主角独白。

## 场景集成

- 在 `SampleScene` 中新增对话 Canvas、底部面板、边框、名称文本、正文文本和操作提示文本。
- 在 `Main Character` 上新增 `DialogueController` 并连接现有移动、交互和物品栏组件。
- 在教授对象或其课堂剧情子对象上新增 `BroadcastDialogueTrigger`，配置上述10页内容。
- `SchoolCorridor` 不新增玩家、摄像机或对话 Canvas；继续复用教室场景中的持久对象。
- 对话播放期间玩家不能进入门或 Portal，因此不允许地图切换与剧情播放同时发生。

## 错误处理

- 空页面数组、空正文、缺失 HUD 或缺失输入组件时输出明确错误并拒绝开始。
- 私聊来源被销毁或离开范围后，从附近来源集合中安全移除。
- 对话请求冲突时保留正在播放的对话，不覆盖页面或输入锁定状态。
- 任何启动后发现的配置错误都通过统一结束路径隐藏面板并恢复输入。

## 验证标准

- `DialoguePlayback` 的逐字推进、翻页门槛、结束和跳过均有测试。
- `DialogueController` 只在空闲时启动私聊，并优先选择最近来源。
- 输入锁定在开始时生效，并在正常结束、跳过和失败时恢复。
- 教授广播只触发一次，包含完全一致的10页内容、名称和顺序。
- 对话 Canvas 位于屏幕底部、排序高于物品栏、默认隐藏，并使用方案 A 配色。
- `R` 在逐字显示期间无效；页面完成后只执行翻页或结束。
- 空格在任意播放阶段结束整段对话。
- 现有移动、碰撞、物品栏、HUD、门和地图切换验证继续通过。
- Unity 编辑器中的最终人工验收覆盖广播自动开始、中文显示、逐字速度、10页顺序、输入锁定、空格跳过及结束后恢复操作。
