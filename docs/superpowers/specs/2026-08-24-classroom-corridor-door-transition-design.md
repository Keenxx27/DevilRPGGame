# 教室门与学校走廊双向切换设计

## 目标

让玩家在教室门附近按 `E` 平滑开启或关闭门。门完全开启后，玩家穿过门外触发区会自动进入独立的学校走廊场景；走廊对应教室门使用相同交互，可将玩家送回教室。往返过程中保持角色、物品栏、借书卡、地面物品和门状态。

## 场景策略

采用 Additive 叠加加载：

- `SampleScene.unity` 作为启动场景和教室地图，始终保持加载。
- 新建 `SchoolCorridor.unity`，第一次离开教室时以 `LoadSceneMode.Additive` 加载，之后不卸载。
- 走廊主体放在与教室相距足够远的世界坐标区域，避免两个已加载地图的渲染和碰撞互相干扰。
- 玩家、主摄像机、物品栏 Canvas 和教室物件继续属于 `SampleScene`，不销毁也不复制，因此现有 `WorldItem` 引用及所有运行时状态天然保留。
- `EditorBuildSettings` 中启用 `SampleScene` 和 `SchoolCorridor`，启动顺序仍以 `SampleScene` 为第一场景。

本方案只保证从 `SampleScene` 开始运行。直接单独运行 `SchoolCorridor` 不属于当前试玩范围。

## 学校走廊地图

`SchoolCorridor.unity` 使用现有 `Basic Unit` 方形 Sprite 和 Transform 拉伸搭建基础占位场景，包含：

- 一块长方形走廊地面。
- 上下边界墙和左右端墙，均带 `BoxCollider2D`。
- 一扇可交互的“教室门”，用于返回当前教室。
- 数扇无交互的装饰门，提供学校走廊的基本识别特征。
- `CorridorFromClassroom` 出生点，位于对应教室门的走廊内侧。
- 走廊镜头锚点，使现有正交摄像机切换到走廊中心。

场景不创建第二个玩家、第二台主摄像机或第二套物品栏 Canvas。

## 门结构与动画

教室现有 `Door Panel` 改为围绕门边铰链旋转：

- `Door` 根对象作为铰链枢轴，门板保持为子对象。
- 根对象挂载 `DoorController` 和用于交互范围的 `CircleCollider2D` Trigger。
- 门板保留 `SpriteRenderer` 和实体 `BoxCollider2D`。
- 初始状态为完全关闭，实体碰撞启用。
- 接受开启请求后，以固定角速度平滑旋转 90°。
- 动画进行期间忽略新的开关请求。
- 只有达到完全开启角度后才禁用门板实体碰撞，并将 `IsFullyOpen` 设为 `true`。
- 接受关闭请求时立即恢复实体碰撞，再平滑旋转回关闭角度。
- 走廊对应门使用相同结构和行为。

门不会在玩家远离时自动关闭，不播放声音，也不显示交互提示；这些均不在当前范围内。

## E 键交互优先级

新增 `PlayerInteraction`，作为 `E` 键的唯一入口：

1. `DoorController` 的交互 Trigger 在玩家进入或离开时，向 `PlayerInteraction` 注册或注销门。
2. 按下 `E` 时，若附近存在门，选择距离最近的门并请求开关。
3. 只要附近存在门，门交互就消耗本次 `E` 输入；即使门正在动画，也不会同时拾取物品。
4. 附近没有门时，调用 `PlayerInventory.TryPickUpNearest()` 执行现有拾取。

`PlayerInventory` 不再自行读取 `E`，但继续处理 `1/2/3` 槽位选择和 `Q` 丢弃。拾取规则、满栏行为与最近物品选择逻辑保持不变。

## 双向传送

新增以下组件：

- `MapSpawnPoint`：以唯一字符串 ID 注册玩家出生位置和摄像机位置。
- `DoorExitPortal`：门外的 `BoxCollider2D` Trigger，引用对应 `DoorController` 和目的出生点 ID。
- `MapTransitionService`：防止重复切换，按需叠加加载走廊场景，查找目的出生点并移动玩家与主摄像机。

流程如下：

1. 玩家按 `E` 开门。
2. 门完全打开后实体碰撞解除。
3. 玩家穿过门外侧的 `DoorExitPortal`。
4. Portal 仅在对应门 `IsFullyOpen` 时请求切换；关闭或动画中的门不会触发。
5. 首次前往走廊时加载 `SchoolCorridor`，等待加载完成后查找 `CorridorFromClassroom`。
6. 将玩家移动到出生点，将主摄像机移动到该出生点指定的镜头位置，并清除玩家刚体速度。
7. 从走廊返回时使用 `ClassroomFromCorridor`，执行相同流程但无需再次加载场景。

传送服务在一次切换完成前忽略后续请求，避免同一帧或连续 Trigger 造成重复加载和重复传送。

## 状态保持边界

由于两个地图均保持加载且复用同一个玩家：

- 三格物品栏及当前选中槽位保持不变。
- 已拾取的借书卡继续由原 `WorldItem` 实例持有，不会复制或重置。
- 已丢弃物品留在丢弃时所在地图的世界坐标。
- 教室门和走廊门各自保持当前开关状态。
- 玩家返回教室时不会重新运行教室场景的初始化。

本阶段不实现退出游戏后的磁盘存档；状态只在当前运行会话中保留。

## 异常处理

- 找不到走廊场景或加载失败时记录明确错误，并解除切换锁，玩家留在当前地图。
- 找不到目的出生点或主摄像机时记录明确错误，不执行不完整传送。
- 重复的出生点 ID 记录配置错误，避免静默选择错误目标。
- Door、Portal 或实体碰撞引用缺失时禁用相应交互并记录配置错误，不影响移动和物品栏。

## 验证标准

- 门关闭时阻挡玩家，按 `E` 后平滑旋转，动画结束前仍阻挡。
- 门完全打开后解除碰撞，玩家可以穿过。
- 再次按 `E` 后恢复碰撞并平滑关闭。
- 门附近的 `E` 只控制门；远离门时 `E` 仍拾取借书卡。
- 门关闭或正在动画时，Portal 不切换地图。
- 完全开门后穿过 Portal，首次加载并进入走廊。
- 走廊对应门可打开，并能自动送回教室。
- 往返后借书卡、物品栏、选中槽位、地面物品和两扇门状态不重置。
- 走廊墙体阻挡玩家，装饰门不产生交互。
- 现有移动、碰撞、拾取、丢弃、Canvas UI 和教室结构回归校验继续通过。
